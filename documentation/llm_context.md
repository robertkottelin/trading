# LLM Context — Grok Decision Layer

The Grok API call (Stage 6) receives a complete snapshot of system state as context every cycle.
This document specifies exactly what data goes in and what rules govern the decision.

---

## Prompt Structure

The full prompt is assembled in this exact order:

```
1. CURRENT TIME: {YYYY-MM-DD HH:MM UTC}

2. ML SIGNAL BLOCK
   (generated by signal_generator.py from 15+ bullish + bearish models)

3. STRATEGY SIGNAL BLOCK
   (generated by StrategyEngine from all 13 strategies)

4. MARKET CONTEXT BLOCK
   (assembled by context_builder.py from market_context_data/)

5. PORTFOLIO STATE BLOCK
   (live dYdX v4 REST query — equity, positions, fills)

6. TRADE HISTORY BLOCK
   (last 20 trades from state_data/trades.jsonl + aggregate stats + equity curve)

7. DECISION HISTORY BLOCK
   (recent decisions from state_data/decisions.jsonl + RISK_LEVEL + streak)

8. INSTRUCTION:
   "Based on ALL the above data, make your trading decision.
    Search the web for any breaking BTC/crypto news.
    Search X/Twitter for real-time crypto sentiment.
    Then output your decision as JSON."
```

**System prompt** is sent as `instructions` (separate from the user prompt, not counted in the conversation).

## Block 2 — ML Signals

```
ML MODEL SIGNALS (N bullish models, M bearish models):

  BULLISH MODELS:
    up_12_0001: prob=0.612 threshold=0.58 → BULLISH (MODERATE) qw=1.0
    up_12_0003: prob=0.531 threshold=0.58 → NEUTRAL            qw=1.0
    up_24_0001: prob=0.589 threshold=0.58 → NEUTRAL            qw=1.0
    ... (all models listed)

  BEARISH MODELS:
    bear_12_0001: prob=0.471 threshold=0.45 → BEARISH (WEAK)   qw=1.0
    bear_24_0001: prob=0.441 threshold=0.45 → NEUTRAL          qw=1.0
    ...

  CONSENSUS: X bullish, Y bearish, Z neutral (total: N+M)
  Weighted score: +0.0412  (range -1 to +1)
```

Key: `bullish_count` = number of bullish models above threshold. `bearish_count` = same for bearish.
Both must be zero for ML to contribute no signal type. Even 1 bearish model firing = absolute LONG veto.

## System Prompt Rules

The system prompt (`SYSTEM_PROMPT` in `grok_client.py`) is ~3000 chars of trading rules sent as `instructions`. Full rule set:

### Signal Type Counting (exact — no improvisation)

| Condition | Signal Types Contributed |
|---|---|
| `bullish_count ≥ 1` | 1 ML type for LONG |
| `bearish_count ≥ 1` | 1 ML type for SHORT |
| `bullish_count = 0 AND bearish_count = 0` | **0 ML types** (neutral ≠ bullish) |
| `≥ 2 strategies agree on direction` | 1 Strategy type |
| Specific confirming data point (price level, funding extreme, OI divergence) | 1 Market Context type |
| General sentiment (F&G extreme, bearish news headline) | **0 Context types** |

**Minimum to trade:** 2 independent signal types. Examples:
- `0 bullish ML + 3 LONG strategies` = 1 type = **NO_TRADE**
- `1+ bullish ML + 2+ LONG strategies` = 2 types = **eligible**
- `0 bullish ML + 2 LONG strategies + price bounce off $65k` = 2 types = **eligible (carefully)**

### Absolute Rules

- **BEARISH ML VETO**: `bearish_count ≥ 1` → NO LONG trades, period. Even prob=threshold qualifies.
- **Confidence threshold**: ≥ 0.62 (NORMAL) / ≥ 0.70 (ELEVATED) / ≥ 0.75 (HIGH)
- **R:R**: target ≥ 1.65:1 to guarantee clearing the 1.5:1 execution check
- **SL width**: ≥ 1.5% for trades ≥60min; ≥ 1.0% for 30–59min. Tighter = noise-stopped.

### Leverage Policy

| USD Notional | Leverage | When to Use |
|---|---|---|
| $20–$100 | 1–2× | Confidence 0.62–0.70 or RISK_LEVEL ELEVATED |
| $100–$220 | 2–3× | 2 clear signal types, confidence 0.70–0.80 |
| $220–$380 | 3–4× | 3+ signal types, confidence 0.80–0.88 |
| $380–$545 | 4–5× | All signals agree, confidence 0.88+ |
| $600 | hard cap | Risk manager enforces |

### SHORT Trade Pathways

Since the system had a historical LONG bias (10 LONGs, 0 SHORTs), both pathways are explicitly documented:

**Pathway A** (bearish ML + strategy):
`bearish_count ≥ 1` AND `≥ 1 strategy signals SHORT` → eligible at $20–$80 moderate size

**Pathway B** (strategy consensus + context):
`≥ 2 strategies SHORT` AND one specific bearish data point:
- funding rate > +0.01% per 8h (longs overpaying)
- price breaking below a named prior support with volume
- OI rising while price falling (trapped longs)

ML neutral does NOT block Pathway B.

### RISK_LEVEL Escalation

| Level | Trigger | Rules |
|---|---|---|
| NORMAL | Default | Standard thresholds above |
| ELEVATED | Recent losses or warning | Confidence ≥ 0.70, require 3 signal types |
| HIGH | 4+ of last 5 trades are SL_HIT | Confidence ≥ 0.80, ML + strategies + price action all agree, strongly prefer NO_TRADE |

### Contrarian Sentiment Rule

F&G < 20 or > 80 is **background context only** — not a signal type.
To act on it, must also have one of:
- Confirming price action (bounce off named support/resistance)
- 2+ ML models aligned
- Trend Following strategy active

### Real-Time Search

Every decision cycle Grok searches:
- **web_search**: breaking BTC/crypto news, macro events, regulatory news
- **x_search**: crypto Twitter sentiment, key influencer calls

These are factored into the final rationale and can shift confidence ±0.05–0.10.

## Output Schema

```json
{
  "direction": "LONG" | "SHORT" | "NO_TRADE",
  "confidence": 0.62,
  "entry_price": 66540,
  "take_profit": 64900,
  "stop_loss": 67540,
  "duration_minutes": 90,
  "position_size_usd": 120,
  "rationale": "2-3 paragraphs covering ML signals, strategy signals, market context, news/sentiment, risk considerations. For NO_TRADE: must state exact conditions needed to trigger."
}
```

**Failure handling**: 2 retries × 5s delay per cycle. After 3 consecutive pipeline-level failures → safe `NO_TRADE` fallback (tracked in `state_data/grok_failures.json`).
